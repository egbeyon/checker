

## Pros

1. By using work-load based constraints to schedule things, it has increased resource efficiency by 30-50 percent - from bin-packing to scheduling and so much more.

2. The APIs are extensible: An AI model can be trained and fed into the Karpenter API and it starts doing predictive analysis on scheduling nodes and seasonality.

3. A lot of cloud providers have their own version, but karpenter is open-source and platform-agnostic.

4. Recommendations on Over-provisioning: A lot of clusters are over-provisioned. Do load-testing and performance-testing of your applications and set good, realistic resource quotas and limits. Knowing your actual resource-needs are super important

5. Rather thancreate resources (nodes) based on availability alone, there should be a tiered-approach and prioritization to resource creation and allocation - resources should not created and handed over to developers because we want the developers to have sufficient resources available to them.
